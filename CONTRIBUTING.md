# Contributing to MagisterialModels

Thanks for your interest in contributing. We welcome focused improvements and constructive discussion.

## Before starting

1. Read the target repository's README and any project-specific contribution instructions.
2. Check existing issues and pull requests for related work.
3. For significant changes, open an issue or discussion to agree on scope before implementation.

## Pull requests

- Keep changes focused and explain their purpose.
- Describe how you tested or verified the change. If testing was not possible, say so.
- Update documentation when user-facing behavior changes.
- Avoid unrelated formatting, refactoring, or dependency changes.
- Do not include secrets, private data, or generated artifacts that do not belong in version control.
- Be responsive to review feedback and maintain a respectful tone.

## Reporting problems

For ordinary bugs, use the relevant project's issue tracker and include reproduction steps, expected behavior, actual behavior, and relevant environment information. Remove secrets and personal data from logs.

For vulnerabilities or other security-sensitive findings, follow [`SECURITY.md`](SECURITY.md) instead of filing a public issue.

## Decisions and reviews

Project maintainers determine priorities and acceptance criteria. Contributions are reviewed for correctness, maintainability, scope, and fit with project goals. Opening a pull request does not guarantee merging.
